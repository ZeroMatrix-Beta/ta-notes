# Analysis II — TA notes

Start with `gemini.md` in the project root. It holds the role, the fidelity policy,
tool usage and the sources, and indexes the two other rule files:

| File | What it holds |
|---|---|
| `style.md` | House style: prose, notation, environments, figures, exercises, provenance conventions |
| `build-and-preamble.md` | Build traps, `main.tex` facts and line numbers, numbering, document layout, the environment set |

Read `gemini.md` plus whichever file covers the task at hand. New rules go in the
file matching their lifetime — that separation is deliberate.

`project-state.md` is **deprecated** and is a stub. There is no file for project
status: `git log` is the record of what has been done. Do not write status anywhere.
